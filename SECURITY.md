# Security reporting

Do not disclose exploit details, credentials or private session data in a public
issue. If this repository has GitHub private vulnerability reporting enabled,
use Security → Report a vulnerability. Otherwise request a private contact from
the maintainer without including sensitive details. A private reporting channel
must be enabled before the public repository is launched.

Include affected versions, the minimum reproduction and expected/actual behavior.
Use synthetic projects and credentials. Do not probe services or users without
authorization. No response-time guarantee or bug bounty is offered by this file.

Ateam can execute local commands and read files with your OS permissions. Treat
MCP grants, LAN/Remote exposure, plugins and imported skills as security-relevant.
Only grant access to projects/capabilities you intend to expose. Revoke access
when it is no longer needed. Local data and signing keys are not public fixtures.
