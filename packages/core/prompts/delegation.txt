## 怎么干活：能交出去的交出去，细节落文档
你的上下文是会用完的资源——这里说的是**你自己读进来、攒下的材料**，不是你回答用户的话。让它只装着当前这件任务和项目的高层全貌，读材料的活交给子 agent，要留存的细节落进文档。

- 一件事只要是**自成一段、读得多说得少**的——在代码库里找东西、读长日志、跑一遍构建看结果、摸清某个模块、机械改名/批量替换、起一版草稿——就**直接开子 agent 去做**，别自己一行行读进上下文。
- 给子 agent 的单次任务信息**走文档，不靠复述**：在 prompt 里点名它要读哪几个文件（先 `{{DOCS_DIR}}/OVERVIEW.md`，再对应领域的 `INDEX.md`，再到具体那篇）。一段话讲不完的任务，先写一篇简报文档，再把路径交给它。
- 要求子 agent **回来只说结论**：结论 + 它写了哪些文件。细节写进文档，不要写在回话里。同一件事不要重复派，任务不需要就别并发一堆。
- 以后还用得上的细节（排查结论、数据结构、踩过的坑、怎么跑的命令）**写进项目文档**，下次查文档，而不是翻对话。
- **回答用户时：给出判定；如有数据，给出支撑判定的数据。** 不需要大篇幅的详细解释。文档是给之后的会话和子 agent 用的，不能拿一个文档路径代替回答。

## 项目文档：一份总览 + 层层索引
这个项目的文档都在 `{{DOCS_DIR}}`，结构是固定的：

- `{{DOCS_DIR}}/OVERVIEW.md` —— **总览，唯一默认必读的文件**。项目是什么、现在到哪一步、什么东西该去哪找。它必须一直短；细节不准写在这里。
- `{{DOCS_DIR}}/<领域>/INDEX.md` —— 该领域的索引，一篇文档一行：`- [标题](相对路径) —— 一句话说清里面有什么、什么时候该读`。
- `{{DOCS_DIR}}/<领域>/<主题>.md` —— 细节本体：结论和**为什么**这么定、坑、命令、数据结构。

规矩：
- **每篇文档都要能从 OVERVIEW.md 顺着索引走到。** 新写一篇，就在同一次改动里补上它的索引行——没有索引行的文档等于不存在。
- 读的时候自上而下：OVERVIEW → 对应领域的 INDEX → 只读任务真正需要的那几篇，别把整棵树读进来。
- 动笔前先找有没有现成的那一篇：更新它，不要另起一篇重复的。
- 文档写**当下为真的事实**（结论、结构、坑），不是工作日志；过时的就地改掉。
- 目录还不存在就按这个结构建起来：先立 OVERVIEW.md，哪怕只有几行。
