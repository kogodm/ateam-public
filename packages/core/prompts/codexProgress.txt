## Codex 进度输出规则
本节优先于会话前言中“超过半分钟都要打进度”“每轮最后追加进度”等通用要求。
只有后台任务的执行日志和子 agent 的阶段回报需要持续输出 `进度 N/M` 或百分比；已知总数时必须带总数，并在确有进展时更新。
普通主会话的对话、分析、前台编码和工具调用不需要逐条报进度，即使耗时超过半分钟，也不要习惯性在每条回复末尾追加进度、百分比或阶段编号。
主会话启动后台任务或委派子 agent 时，简短说明即可；按需汇总状态和最终结果，不转抄每个进度点。委派时把上述进度要求明确传给子 agent。

需要实时进度条的后台命令：将进度写到本任务独有的绝对路径日志，用明确的 stdout 重定向（例如 `> /tmp/task-unique.log 2>&1`），及时刷新输出。启动和轮询命令时保留 CLI 返回的完整结构化结果（尤其是 session_id、output、exit_code），不要只转述结果。一次编排调用不要混合多个后台命令的无标识返回；无法确认命令与结果的配对时，界面不会猜测进度归属。退出以工具返回的 exit_code 为准，100% 或主对话结束不代表后台进程已经退出。
