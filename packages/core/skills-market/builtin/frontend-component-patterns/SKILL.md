# 何时使用

- 新建可复用组件，或既有组件 props 越加越多、难以维护时。
- 多个组件共享一段状态逻辑，想抽成 hook 时。
- 列表渲染卡顿、组件频繁重渲染需要定位时。

# 执行步骤

1. 先定受控还是非受控：表单场景默认非受控（`defaultValue` + ref），仅当外部需要实时读值/联动时才升为受控（`value` + `onChange`）。二者别混用，会报 warning。
2. 用组合代替配置：能用 `children` / slot 传入的，就别加 `showHeader`、`headerType` 这类布尔/枚举 props。`<Card><Card.Header/></Card>` 优于十个开关。
3. props 设计遵循最小接口：只暴露调用方真正要控制的东西；回调命名统一 `onXxx`，值命名与 HTML 语义对齐；避免透传整个对象，只传所需字段。
4. 状态就近原则：只被单个组件用的状态留在局部；两个兄弟组件都要读写才提升到最近公共父级。别一上来全塞 Context 或全局 store。
5. 副作用隔离：数据请求、订阅、DOM 操作放进 `useEffect` 或自定义 hook，渲染函数保持纯函数。清理函数（`return () => ...`）必须写，避免泄漏。
6. 抽 hook 的判据：同一段逻辑在 ≥2 处出现且行为一致，才抽 `useXxx`；抽出后 hook 只管逻辑与状态，不返回 JSX。
7. 渲染性能：长列表给稳定唯一 `key`（禁用数组下标）；确认某子树因父级重渲染而无谓更新时，再上 `memo` + `useCallback`/`useMemo`。

# 常见坑

- 过早抽象：只有一处用就抽公共组件，参数越加越多变成"万能组件"，比复制粘贴更难维护。等出现第三次重复再抽。
- 用数组下标当 key，列表增删/排序后状态错位、输入框内容串行。
- `useEffect` 依赖数组漏项或乱填 `[]`，导致闭包读到旧值或该更新时不更新。
- 到处上 `memo` 却忘了回调/对象每次新建，`memo` 完全失效还增加了对比开销。
- 受控组件忘了 `onChange`，输入框变成只读，用户打不了字。

# 检查清单

- [ ] 受控/非受控二选一，未混用
- [ ] 能组合就没用布尔配置 props
- [ ] 状态放在最近的合理层级，未过度全局化
- [ ] 副作用都在 hook/effect 内，渲染保持纯净
- [ ] effect 依赖数组正确、清理函数齐全
- [ ] 列表 key 稳定唯一，非数组下标
- [ ] memo/useMemo 仅用于已确认的性能热点
- [ ] 未在只用一次的地方过早抽象
