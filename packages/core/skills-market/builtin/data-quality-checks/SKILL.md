# 何时使用

- 交付一张表 / 一份报表前,或让下游依赖某数据源前。
- 报表数值突变、被质疑"数据对不对"时。
- 建设数仓、需要给关键表加持续质量监控时。

# 执行步骤

1. 覆盖五个维度:完整性(不缺行 / 不缺关键字段)、唯一性(主键不重)、一致性(跨表口径一致)、及时性(按时产出)、有效性(值在合理范围 / 枚举内)。
2. 监控行数与分布:记录每日行数、按维度分布,设同比 / 环比阈值,行数骤增骤降立即告警。
3. 校验空值与异常值:关键字段空值率不超阈值;数值型看最小 / 最大 / 分位数,识别负数、离群点、突刺。
4. 做跨表对账:与源系统或上游汇总表核对总量(如订单数、金额),差异超容忍度就阻断。
5. 用断言固化规则:主键唯一、外键存在、金额非负、枚举合法等写成可执行断言(如 dbt tests / 自定义 SQL 校验)。
6. 定阻断策略:核心校验失败 → 阻断下游发布(fail closed);次要校验失败 → 告警但放行(warn),分级处理。
7. 建质量看板:把各表的检查通过率、失败历史、新鲜度集中展示,让问题可见、可追溯、有 owner。

# 常见坑

- 只查行数不查分布:总量没变但某渠道归零也发现不了。
- 唯一性没校验:主键重复导致下游 join 翻倍、指标虚高。
- 空值率靠肉眼:关键字段悄悄大面积为空,拖几天才发现。
- 无跨表对账:管道内部自洽但和源系统早已偏离。
- 所有校验都只告警不阻断:坏数据照样流到看板和决策。
- 只在上线时查一次,之后不做持续监控。

# 检查清单

- [ ] 完整性/唯一性/一致性/及时性/有效性五维都有检查
- [ ] 行数与关键维度分布有阈值监控
- [ ] 关键字段空值率、数值异常值有校验
- [ ] 与上游/源系统做过跨表对账
- [ ] 核心规则写成可执行断言并纳入调度
- [ ] 阻断(fail)与告警(warn)分级明确
- [ ] 有质量看板,失败可追溯到 owner
