# 何时使用

- 开发任何面向公众的页面、表单、交互组件（弹窗、下拉、标签页）时。
- 用 `<div onClick>` 做按钮/链接，或自研了原生控件没有的交互控件时。
- 上线前做可访问性验收，或收到屏幕阅读器/键盘用户反馈时。

# 执行步骤

1. 优先语义化标签：按钮用 `<button>`、链接用 `<a href>`、标题用 `<h1>-<h6>` 且层级不跳级、列表用 `<ul>/<ol>`。语义标签自带焦点、键盘、语音角色，省掉大量 ARIA。
2. 保证键盘可达：所有交互元素能用 Tab 到达、Enter/Space 触发；顺序符合视觉阅读顺序；不要用正数 `tabindex`（只用 0 或 -1）。
3. 管理焦点：打开弹窗时把焦点移入并锁在弹窗内（focus trap），关闭后归还到触发元素；路由切换后把焦点移到新页面主标题。
4. ARIA 是补充不是替代：原生标签能表达就别加 ARIA；确需时用 `aria-label`/`aria-labelledby` 补名称，用 `aria-expanded`/`aria-current` 表状态，用 `role` 补自研控件角色。错误的 ARIA 比没有更糟。
5. 表单可用：每个输入框都有关联 `<label for>`（或包裹式 label）；错误提示用 `aria-describedby` 关联并加 `aria-invalid`；必填用 `required` 而非仅靠红星。
6. 视觉可辨：正文文字对比度 ≥ 4.5:1、大号文字/图标 ≥ 3:1；不要仅靠颜色传达信息（错误同时加图标或文案）。
7. 图片 alt：有信息的图写描述性 alt；纯装饰图用 `alt=""` 让阅读器跳过；功能性图标（如仅图标的按钮）在按钮上给文字标签。
8. 用屏幕阅读器实测：VoiceOver（Mac，Cmd+F5）或 NVDA（Windows）走一遍关键流程，只用键盘不用鼠标。

# 常见坑

- 用 `<div>`/`<span>` + `onClick` 造按钮：键盘按不了、阅读器不识别、没有 focus 样式。
- 给所有元素堆 ARIA，`role` 与实际行为不符，反而误导辅助技术。
- 弹窗打开后焦点仍留在背景，键盘用户被困在看不见的地方。
- 用 `outline: none` 去掉焦点圈却不给替代样式，键盘用户完全看不到当前位置。
- 占位符 `placeholder` 当 label 用，输入后提示消失、对比度还常不达标。
- 仅用红色文字表示报错，色觉障碍用户无法感知。

# 检查清单

- [ ] 交互元素用原生语义标签
- [ ] 全流程可纯键盘操作，Tab 顺序合理
- [ ] 弹窗/浮层有焦点锁定与归还
- [ ] ARIA 仅在必要处使用且正确
- [ ] 每个表单控件有关联 label，错误有关联提示
- [ ] 文字对比度达标，不单靠颜色传达信息
- [ ] 图片 alt 区分信息图与装饰图
- [ ] 至少用一款屏幕阅读器实测过关键路径
