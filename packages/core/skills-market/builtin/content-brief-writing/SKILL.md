# 何时使用

- 要委托他人（写手/设计/外包）产出一篇内容，需要一份说明"写什么、给谁、达成什么"的输入时。
- 内容产出反复跑偏、改稿多轮，根因是开工前没对齐目标时。
- 批量生产内容，需要统一受众、语气与质量基线时。

# 执行步骤

1. 定受众与意图：写清目标读者是谁（角色、认知阶段、痛点），以及他们读这篇处于什么意图阶段（认知/考虑/决策）。
2. 提炼核心信息(one message)：全文只服务一句话主张，读者读完只需记住这一点。一篇塞多个主张等于没有主张。
3. 搭结构大纲：用小标题列出从钩子→论证→行动的骨架，标注每段承担的作用，别让写手自由发挥后再返工。
4. 明确关键词与 SEO 意图：给出主关键词与相关长尾词，说明搜索者背后的真实意图，让内容匹配"用户想解决的问题"而非堆词。
5. 设定 CTA：写清读者读完应做的下一步（订阅/试用/联系/转发）以及落点链接，一篇一个主 CTA。
6. 约定语气与品牌：给出语气基调（如专业克制/轻松口语）、可用与禁用词、品牌口径与合规红线，最好附正反例。
7. 定成功指标：明确用什么衡量这篇有效（阅读完成率、转化点击、留资、分享数），以及基准值。
8. 附参考与约束：字数范围、截稿时间、可引用来源、需规避的竞品措辞等一并给全。

# 常见坑

- 自嗨式堆砌：通篇讲"我们多厉害"，不解决读者的问题，受众划走。核心信息必须站在读者收益一侧。
- 没有单一核心信息，想一篇讲清所有卖点，结果什么都没讲清。
- 关键词硬塞、脱离搜索意图，既伤阅读又不再被搜索引擎奖励。
- CTA 缺失或一篇放三四个，读者不知道该干嘛。
- 语气无约束，多人协作时品牌调性漂移，稿件风格各异。
- 只写"要写什么"不写"怎么算成功"，无法复盘和迭代。
- 大纲缺失，把结构判断全甩给写手，改稿轮次翻倍。

# 检查清单

- [ ] 受众画像与意图阶段写清楚了
- [ ] 只有一个核心信息(one message)，且落在读者收益上
- [ ] 有标注段落作用的结构大纲
- [ ] 主关键词/长尾词及其搜索意图已给出
- [ ] 有且仅有一个主 CTA，落点明确
- [ ] 语气、品牌口径、禁用词/合规红线已约定
- [ ] 成功指标与基准值已定义
- [ ] 字数、截稿、参考来源等约束齐全
