# 何时使用

- 规划新页面 / 内容、想从搜索引擎获取自然流量时。
- 页面已上线但没有收录、没有排名、点击率低时。
- 网站改版、迁移 URL、需要避免流量流失时。

# 执行步骤

1. 先定搜索意图:围绕目标关键词判断用户想要什么(信息 / 导航 / 交易),让页面内容与意图匹配,而非硬塞关键词。
2. 写好标题与 meta:`<title>` 唯一、含核心词、控制在约 60 字符内;meta description 写成吸引点击的摘要(约 150 字符),每页不同。
3. 规划信息架构与内链:URL 语义清晰、层级浅;用面包屑和上下文内链把相关页面连起来,帮爬虫和用户发现内容。
4. 保证页面速度与移动端:优化 Core Web Vitals(LCP / CLS / INP),图片压缩 + 懒加载,移动端优先、响应式布局。
5. 加结构化数据:用 Schema.org(Article、FAQ、Product、Breadcrumb 等)标注,争取富媒体摘要,提升展现与点击。
6. 保证可抓取可索引:检查 robots.txt、sitemap.xml、canonical 标签,避免重要页被 noindex 或重复内容稀释权重。
7. 建立衡量闭环:用 Search Console 跟踪收录数、排名、曝光、点击率(CTR),按数据迭代标题和内容。

# 常见坑

- 关键词堆砌:标题 / 正文塞满重复词,伤害可读性并触发降权。
- 多页 title / description 雷同,搜索结果无区分度、CTR 低。
- 内容与搜索意图错位:交易词却给一篇泛泛科普,跳出率高。
- 忽视移动端和速度:慢页面直接被降权,用户也流失。
- 改版换 URL 不做 301 跳转,历史权重和收录全丢。
- 只看排名不看点击:排名高但标题没吸引力,CTR 依然差。

# 检查清单

- [ ] 页面内容匹配目标关键词的搜索意图
- [ ] title 唯一含核心词,meta description 逐页不同
- [ ] URL 语义清晰,层级浅,内链合理
- [ ] Core Web Vitals 达标,移动端友好
- [ ] 关键页面加了 Schema.org 结构化数据
- [ ] robots/sitemap/canonical 正确,重要页可索引
- [ ] 无关键词堆砌
- [ ] Search Console 跟踪收录/排名/CTR 并迭代
