# 何时使用

- 新建一个指标、或团队对某指标数值有争议时。
- 做 A/B、周报、OKR 需要选定衡量口径时。
- 发现"同名指标不同团队算出不同值"时。

# 执行步骤

1. 写下四要素:分子、分母、时间窗、去重口径。缺一个,指标就是模糊的。例:次日留存 = 次日回访去重用户数 / 当日新增去重用户数。
2. 明确统计对象与过滤条件:是否含内部账号 / 测试流量 / 已退款订单?一次性写清 include/exclude 规则。
3. 区分北极星指标与护栏指标:北极星衡量核心价值(如周活跃创作用户),护栏防止副作用(如崩溃率、退款率、客诉),两者配套定义。
4. 剔除虚荣指标:优先选与留存 / 收入 / 价值强相关的指标,而非"累计注册数""PV"这类只涨不跌、无法指导决策的数字。
5. 设计维度切分:按渠道 / 版本 / 地区 / 新老用户预留可下钻维度,但先定义好总口径再切分,避免"辛普森悖论"。
6. 口径版本化:每次口径变更(改过滤、改时间窗)记为新版本 v1/v2,标注生效日期,历史数据不要静默重算。
7. 跨团队对齐:把定义、SQL、样例数值写进指标字典,让数据 / 产品 / 运营用同一份定义,评审通过再上线。

# 常见坑

- 只说"留存率"不说是第几日、按什么去重,导致鸡同鸭讲。
- 分母选错:用"全体用户"当分母稀释了新功能的真实转化,应按"触达用户"。
- 时间窗漂移:有的图按自然日、有的按滚动 7 日,对比时张冠李戴。
- 静默改口径:悄悄改了过滤条件,曲线突变被误判为业务波动。
- 追逐虚荣指标:累计下载量好看但不反映活跃,误导资源投入。
- 平均值掩盖分布:人均时长被少数重度用户拉高,应看中位数 / 分位数。

# 检查清单

- [ ] 分子/分母/时间窗/去重四要素齐全
- [ ] include/exclude 过滤规则写明(测试流量、退款等)
- [ ] 北极星与配套护栏指标都已定义
- [ ] 不是虚荣指标,与核心价值相关
- [ ] 预留可下钻维度,且先定总口径
- [ ] 口径有版本号与生效日期
- [ ] 已进指标字典并跨团队评审对齐
